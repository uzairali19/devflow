# Devflow v2 — the engineering OS

v1 was dotfiles plus an installer. v2 adds the layer above the tools:
workflows, structure, and memory. This document records the design and —
more importantly — what was deliberately *not* built.

## Design rules

1. **Never wrap a perfect command.** `ssh paws`, `git status`, `docker ps`
   stay untouched. A devflow command must *combine* several operations into
   one meaningful workflow, or it doesn't exist.
2. **No parallel state.** `~/.ssh/config` is the server inventory. git is
   the project registry. devflow reads what already exists.
3. **Markdown beside the code.** Decisions, journals, mistakes, and
   research live in the project repo — not in an app.
4. **Plain bash, small files.** Any file you can't read in one sitting is
   a bug.
5. **Create, never clobber.** Generators open existing files instead of
   overwriting; `project init` refuses to touch existing paths.
6. **Nothing personal in git.** Hosts live in `~/.ssh/config`; secrets in
   `~/.zshrc.local` / `.env` (both ignored). Only templates are committed.

## Layout

```text
bin/devflow      dispatcher — core commands, sources lib/ on demand
lib/             one file per command group
  common.sh        log/die/confirm/slug/edit_file/replace_tokens
  health.sh        devflow health <host>
  notes.sh         journal / adr / notes generators
  project.sh       project init / open
scripts/         installer steps (unchanged from v1)
configs/         dotfiles (unchanged from v1)
templates/       project scaffold — markdown only, no code
training/        10 lessons: concept, example, exercises, mistakes, reading
docs/            per-tool deep dives + this file
```

## The commands and why they exist

| Command | Replaces | Rule it satisfies |
| --- | --- | --- |
| `status` | 6+ commands: git status/log, docker compose ps, rg TODO, ls decisions/ journal/ | removes repetitive work |
| `health <host>` | a 10-command manual sweep over ssh | production debugging |
| `journal today` | remembering the path, date, and section format | removes remembering |
| `adr new "T"` | remembering the ADR format and naming scheme | standardises workflow |
| `project init` | recreating structure by hand, differently each time | standardises workflow |
| `project open` | cd + tmux session dance | removes repetitive work |
| `notes today` | scattered scratch files | removes remembering |
| `session/sessions/doctor/debug/update/path` | (v1, unchanged) | |

`devflow status` is context-aware: inside a git repo it's a project
dashboard (branch, working tree, recent commits, compose services, env
sanity including an un-ignored `.env` warning, TODO count, latest
ADR/journal). Outside one, it's a short devflow self-check.

`devflow health <host>` takes anything `ssh <host>` accepts. One ssh round
trip runs a read-only report: host/kernel, uptime/load, cpu, memory, disk,
docker containers, listening ports, journal errors (24h), tailscale,
firewall, pending updates. Sections degrade gracefully when a tool or sudo
is missing.

## Rejected (and why)

- **`devflow ssh NAME`** — wraps a perfect command. `ssh paws` already wins.
- **`servers.toml` inventory** — parallel state that drifts from
  `~/.ssh/config` and begs to be committed with real IPs. Deleted after
  being half-built; the ssh config is the single source of truth.
- **`devflow experiment new`** — a template file is enough; not every
  markdown file needs a generator.
- **TODO/task manager, tagging, search commands** — `rg` and the journal
  already do this. Building an app violates the philosophy.
- **TUI dashboards, JSON config, plugin system** — devflow stays shell,
  composable, readable.

## Future (deliberate, not promised)

- `devflow health` over several hosts in one run (loop + summary table)
- `devflow status` learning per-project checks from a committed
  `.devflow.md` marker — only if a real need appears
- shell completion for the subcommands
